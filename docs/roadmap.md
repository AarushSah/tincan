# Remaining work

[← tincan](../README.md)

These are proposals, not commands to rely on. None of them is implemented. Deliver working slices, and remove an item once it is verified.

- **Marking conversations as read.** Reading never changes unread state today, on purpose: marking a message read can send a read receipt the other person sees. Messages' AppleScript has no way to do it, and the database must not be written. A design would open the conversation in Messages through Accessibility, as the typing indicator does, and only on an explicit request.
- **Tapbacks, inline replies, edits and unsend.** Messages' AppleScript sends only text and files. These actions need Messages' private framework from inside the Messages process, which means injecting a helper into Messages. macOS allows that only with System Integrity Protection and library validation turned off, which lowers the security of the whole Mac, and private interfaces break with macOS updates. If this is ever built, it would be a separate, clearly labelled opt-in component, never required and never enabled by default.
- **Scheduled sends.** Send at a time, with the same pacing and confirmation. tincan has no background process today; this needs a launchd job with a durable queue that survives sleep, a clear answer for a send whose time passed while the Mac was off, and permissions granted to tincan itself, since a launchd job that runs tincan directly doesn't get a terminal's.
- **Homebrew formula and signed releases.** A Developer ID signed and notarized binary, published as a release and installable with Homebrew, so installing doesn't need a Swift toolchain. `scripts/release.sh` builds, signs, notarizes and packages the archive, and `packaging/homebrew/tincan.rb` is a formula template. Publishing needs a Developer ID certificate, notarization credentials and a tap repository for the formula.
- **Typing indicator in groups.** Keyboard mode opens one-to-one conversations by address. Groups have no such link, so tincan would need a dependable way to select a group in the Messages window by its conversation, not its title, before it could type there.
- **MCP server.** Expose the same operations to assistants that don't run shell commands, backed by TincanKit and the same identity, exclusion and confirmation rules. It must not become a second interface that drifts from the CLI.
- **A typedstream reader in Swift.** Message bodies are decoded with Apple's `NSUnarchiver`, the decoder Messages itself uses, with a byte scanner as the fallback. `NSUnarchiver` is deprecated, creates whatever classes an archive names, and runs only on macOS. A reader for the typedstream format written in Swift would read the text, attachments, mentions and parts without it, and let the decoding tests run anywhere. Write it from the format itself: the best-known implementation, crabstep, is GPL-licensed.
